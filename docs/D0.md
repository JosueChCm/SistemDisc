Gestión de ajustes razonables para estudiantes con discapacidad · Oficina de Bienestar Universitario

---

## 1. Contexto y problema

Cada semestre, la Oficina de Bienestar Universitario de una universidad pública atiende a estudiantes con discapacidad que piden ajustes razonables para cursar sus asignaturas: tiempo adicional en evaluaciones, materiales en formato accesible (texto ampliado, lector de pantalla, Braille), intérprete de lengua de señas peruana, aula en primer piso, mobiliario adaptado o acompañamiento en laboratorio.

Hoy las solicitudes llegan por correo, WhatsApp o en papel. No hay un registro central y cada canal lo atiende una persona distinta de la oficina.

Por eso se pierden solicitudes, la oficina no sabe cuáles están pendientes, no puede avisar al docente qué ajuste le toca a cada estudiante y no se genera el reporte anual que piden la Ley N.° 29973 (Ley General de la Persona con Discapacidad) y la Ley Universitaria N.° 30220.

Se necesita una aplicación web interna que junte el registro y el seguimiento de las solicitudes. Los propios estudiantes con discapacidad visual van a usar el formulario de solicitud.

## 2. Actores

| Actor | Descripción | Qué necesita del sistema |
|---|---|---|
| Estudiante con discapacidad | Estudiante matriculado que, por su condición, necesita uno o más ajustes razonables para sus asignaturas. | Registrar su solicitud de ajuste razonable y saber si fue aprobada. |
| Oficina de Bienestar Universitario | Unidad que recibe, evalúa y da seguimiento a las solicitudes. | Registrar estudiantes, cambiar el estado de las solicitudes, ver lo pendiente y sacar el reporte semestral. |
| Docente | Profesor de la asignatura donde se aplicará el ajuste. | Aprobar o rechazar los ajustes pedidos para su asignatura. |

## 3. Historias de usuario

**H1.** Como personal de la Oficina de Bienestar, quiero registrar al estudiante con su tipo de discapacidad y su documento acreditador para tener sus datos centralizados.
*Criterio de aceptación:* DADO un estudiante no registrado, CUANDO la oficina ingresa sus datos, el tipo de discapacidad y adjunta el certificado CONADIS o el certificado médico en PDF, ENTONCES el sistema guarda el registro correctamente.

**H2.** Como estudiante con discapacidad, quiero registrar una solicitud de ajuste razonable para una asignatura para no tener que enviarla por correo o WhatsApp.
*Criterio de aceptación:* DADO un estudiante registrado, CUANDO completa el formulario de solicitud, ENTONCES el sistema registra la solicitud de forma rápida y sencilla.

**H3.** Como personal de la Oficina de Bienestar, quiero cambiar el estado de una solicitud y avisar al docente para mantener informados a todos los involucrados.
*Criterio de aceptación:* DADO una solicitud registrada, CUANDO la oficina selecciona un nuevo estado (recibida, evaluada, observada, aprobada, implementada), ENTONCES el sistema actualiza el estado y envía un correo al docente de la asignatura.

**H4.** Como personal de la Oficina de Bienestar, quiero ver las solicitudes pendientes para saber qué debo atender.
*Criterio de aceptación:* DADO que existen solicitudes registradas, CUANDO la oficina ingresa al listado, ENTONCES el sistema muestra todas las solicitudes.

**H5.** Como sistema, quiero calcular el total de solicitudes por tipo de ajuste para generar el reporte para la autoridad.
*Criterio de aceptación:* DADO el cierre del semestre, CUANDO se solicita el reporte, ENTONCES el sistema muestra los totales por tipo de ajuste en un gráfico de barras.

**H6.** Como estudiante con discapacidad visual, quiero que el formulario sea compatible con mi lector de pantalla para poder usarlo sin ayuda.
*Criterio de aceptación:* DADO un estudiante con discapacidad visual, CUANDO usa el formulario de solicitud, ENTONCES el estudiante queda satisfecho con la experiencia de uso.

## 4. Alcance

**Dentro del alcance (este semestre)**

1. Registrar al estudiante con su tipo de discapacidad y el documento que la acredita.
2. Registrar solicitudes de ajuste razonable por asignatura, ingresadas por el estudiante o por la oficina.
3. Cambiar el estado de cada solicitud.
4. Listar lo pendiente por estudiante y por asignatura.
5. Obtener el total de solicitudes por tipo de ajuste y por estado para el reporte semestral.
6. Avisar automáticamente al docente por correo cuando una solicitud sea aprobada.

**Fuera del alcance**

- Cargar o guardar archivos adjuntos (certificados, informes médicos).
- Integración con CONADIS, con el sistema académico de matrícula o con SUNEDU.
- Notificaciones automáticas por correo o WhatsApp.
- Evaluación médica o calificación de la discapacidad.
- Aplicación móvil nativa.
- Programación de horarios y asignación de aulas.

## 5. Supuestos y restricciones

**Supuestos**

- La oficina tiene al menos un responsable que actualiza el estado de las solicitudes durante todo el semestre.
- Los estudiantes y el personal entran con su código o correo institucional.
- El número de documento CONADIS se valida automáticamente con el registro nacional del CONADIS.
- Los tipos de ajuste razonable no cambian durante el semestre.

**Restricciones**

- Es una aplicación web de uso interno, solo accesible desde la red de la universidad.
- Tecnologías: Python 3.11+, FastAPI, frontend con HTML y JavaScript simple, SQLite, Git y GitHub.
- Para agilizar las pruebas se usarán los datos reales de los estudiantes atendidos por la oficina el semestre anterior.
- El formulario de solicitud usará un calendario emergente y la selección de asignaturas arrastrando y soltando, para que sea más visual.
- El sistema no evalúa si el ajuste es pertinente médicamente ni reemplaza la decisión de la oficina.

## 6. Requisitos candidatos

**Requisitos funcionales (RF)**

| N.° | Requisito funcional |
|---|---|
| RF1 | El sistema deberá registrar al estudiante con su tipo de discapacidad y el documento que la acredita. |
| RF2 | El sistema deberá permitir que la oficina registre una solicitud de ajuste razonable para una asignatura. |
| RF3 | El sistema deberá permitir cambiar el estado de la solicitud. |
| RF4 | El sistema deberá listar las solicitudes pendientes. |
| RF5 | El sistema deberá generar el reporte anual con el total de solicitudes por tipo de ajuste. |
| RF6 | El sistema deberá tener una interfaz amigable e intuitiva para todos los usuarios. |

**Requisitos no funcionales (RNF)**

| N.° | Requisito no funcional |
|---|---|
| RNF1 | La aplicación deberá ser accesible para personas con discapacidad visual y funcionar correctamente con lectores de pantalla. |
| RNF2 | El sistema deberá ser rápido y seguro: cargar las páginas en poco tiempo y proteger los datos de los estudiantes con encriptación. |
